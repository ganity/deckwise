## Ownership

### Imported PPT teaching entry

An imported task replaces the generic empty Chat welcome with a teaching setup
card. Its source is the current session's persisted import path, not transcript
presence. Start requests missing narration, spoken audio, spotlight/highlight and
teaching animations without feature checkboxes or extra settings. Existing narration
and matching audio remain unchanged. Quiz/activity counts and insertion positions
are inferred from actual content, objectives, existing activities and lesson plans,
respecting explicit requirements and page limits. Reuse suitable existing activities;
add only needed independent pages, never convert existing body pages.

The card submits directly through the existing session-targeted `sendPrompt`,
including the selected audience and material attachments with plan/script roles.
It adds no renderer generation loop, teaching authority or automatic publication.
Inputs are draft UI state until submission; accepted requirements live in the
normal Chat history. Draft settings and unattached material selections do not
survive a full renderer restart. Accepted submission hides the entire setup card;
Chat owns progress, stopping and continuation thereafter. Persisted user/tool messages
keep it hidden after reopening, including stopped or failed generation. Initial
submission rejection preserves setup and attachments for retry.

The editor must match the imported path, be writable, ready and saved before a
generation request can be submitted. A synchronous submission fence prevents
double clicks. Session/unmount/account changes invalidate pending reads and file
picker results. Failed sends retain selections and attachment references. Real
saved teaching data supplies pre-start page/audio counts. These counts are not
acceptance or quality claims. No card reads continue after handoff to Chat.
Preview/check reuse existing immutable snapshot, fixed build, warning review and
inspection components. Existing publish gates remain authoritative.

PPT Master SVG inspection remains mounted after adoption. Resolve its project
from the saved source path before falling back to chat tool history. Open the
first available SVG once during generation, allow manual reopening after export,
and fence asynchronous preview responses when the session/project changes.
Preview reads do not share the model-turn mutation lock or authorize export.

Scene planning counts cover, opening, illustrated setup and review pages within
the saved body-page budget. Story beats map onto those pages; they do not create
additional pages. Explicit total limits include the separate assessment pages.
Automatic plan validation exposes the same bounded product validation error as
explicit submission. Two rewritten corrections remain available when the model
resubmits an unchanged invalid draft; repeated unchanged failures are bounded
separately. Exhausted recovery ends with a truthful failure report. The reporting
request retains tool schemas for provider replay compatibility with
`tool_choice: none` and the execution fence. A noncompliant final tool call is
blocked with the latest saved acceptance, then receives at most one plain-language
reporting correction without reopening execution. A reporting block does not undo
saved results or imply missing media; completion and assessment readiness remain
authoritative, with non-blocking quality diagnostics reported separately. Later
user requests reset this guard.

The existing main Chat owns requirements and generation progression. The work
panel remains an inspection/editing entrance. Task types remain `plain`, `scene`
and `import`; school stage is guidance, not routing. No second assistant, model
loop in the renderer, database owner or generation engine is introduced.

media operations retain the session supplied by Main's live turn. Main's turn

### Ordinary presentation teaching handoff

The official SVG preview and explicit Generate PPTX gate remain required.
Before SVG authoring, plan one teaching entry per physical page using
`courseware_presentation_adopt`'s schema. Opening, setup and review consume the
body-page budget; standalone Quiz and checkpoint pages must fit the requested
total page budget. Each Quiz page contains one structured MAIC question, using
A-D option keys (T/F for judge). Each classroom interaction has one exact,
editable question text box and a reference answer. Assessment pages cannot also
carry body narration, required objects, effects, music or video.

For new projects, `courseware_presentation_prepare` saves that ordered plan in
`presentation-plan.json` and renders assessment SVGs through the existing shared
Quiz/checkpoint projection. Its file list reserves one `NN.svg` per physical page;
the model authors only body entries. Fixed pages contain editable student-facing
text and shapes, never reference answers, grading constraints or lecture/effects.
Returned template font sizes must be declared as named assessment typography in
the design spec and lock; the official quality gate still checks every SVG.
Long questions wrap within one editable text box. Identical preparation is safe
to replay; changed/manual artifacts are conflicts and are never overwritten.
Preparation does not touch exported/native content, call suppliers or authorize
export. Once a source is attached, resume saved teaching instead of preparing it
again. Adoption must match the saved plan; plan changes invalidate previous
validation and exports. Projects created before this manifest remain compatible.

After the authorized official export, Main parses its actual bytes and creates
canonical scenes using Host page UUIDs. The finite `courseware.presentation.adopt`
RPC verifies the workspace export path, current final SVG quality report,
planning/notes freshness, source hash, physical page count and body-page budget.
Host saves page-bound `metadata.teachingRequirements` and attaches the source
to the ordinary task. Detailed narration reads trusted parsed notes and page
evidence; missing assessment notes never trigger legacy body-note initialization. Replays
retain the same plan and saved teaching; they never reconstruct edited content.
No new database schema or alternative presentation exporter is introduced.

Saved narration, object-grounded highlight/spotlight/animation, speech TTS,
question TTS and Quiz option images use the same services and editor/player as
scene and imported courses. Outline notes do not count as detailed narration.
Explicit `requiredEffects` remain incomplete until saved pending cues or timed
cues satisfy them. Ordinary visual observations use actual parsed object IDs,
without creating scene-only semantic storage. Requirements follow logical page
identity during native save/reorder. Once Office editing starts, resume saved
teaching instead of overwriting the deck from SVG.

`courseware_presentation_adopt` continues the teaching-course turn by default,
including when the model omits `continueTeaching`. Export confirmation in this
courseware task is not a PPTX-only completion boundary. The export action names
the teaching handoff and requests narration, synchronized effects, speech and
assessment media under the existing credits policy. An explicit PPTX-only or
no-audio request must pass `continueTeaching:false` and starts no additional
media generation. Scene compilation and status-only media reads retain their
existing explicit opt-in semantics. Completion includes missing question speech and
option images, not merely successful PPTX export. Restart resumes the existing
saved project and original media requests through the shared continuation tools.

The main-window-only `deckwise/courseware/workflow/get` IPC accepts exactly
`{sessionId}`. Main validates the active viewing Chat, stable Host and workspace.
Chats without a saved task show no automatic courseware entrance. Failed reads remain actionable.
The shell publishes the viewing session in its layout effect before child
passive effects read scoped workflow state. Reloading or reopening a saved Chat
must not depend on a new Agent turn to establish its owner.

## Single courseware workspace

Chat keeps the conversation and a compact Open courseware / edit entrance above
its transcript. There is no workflow card in either composer. A newly created
courseware task opens the right workspace only when it has no retained panel
resources. Later messages and session restoration preserve existing panel tabs,
collapsed state and native editor state. The old `scene-images` entrance maps to
`ppt`; opening the same attached PPT reuses that workspace.

The workspace replaces the disabled task-settings form and manual image console.
Task creation still owns the three routes and education settings. Scene planning
uses the approved version's actual title, pages and visual guide. Confirm plan
pins that hash and sends a specific cover-generation continuation. Confirm style
adopts the verified cover with the existing selection CAS, then sends a specific
remaining-pages continuation. Cover revisions accept an explicit instruction.
Plan changes still invalidate their affected approval and assets. Failed sends
remain visible and can be resumed without repeating approval.

Cover confirmation continues the original requested deliverables, including
previously requested narration, speech audio and music. Its localized message
does not introduce a new full-course decision or expand a PPTX-only request.
Already supplied requirements are not asked again.

ToolSearch activation of compilation or any saved narration/media workflow tool
also activates the finite saved-teaching tool group (narration context/propose,
media context/prepare/refresh). Activation receipts record every added name for
normal replay and restart recovery. Mode and Host authorization checks still
apply independently; discovery never executes generation. Saved narration
context uses the same bounded tool budget as saved media context so parser
admission and source verification can finish without a premature outer timeout.

## Task creation and handoff

The new-task dialog participates in the work-panel native-surface blocker, as
does global search. Both direct-file and courseware Office mounts hide their
isolated view while blocked and restore it on dismissal without closing or
reopening the document. Late native readiness cannot override a blocker. The
courseware publish/import dialog also blocks its underlying Office view.

The three-route creation dialog accepts an optional brief, audience/grade and
subject. Textbook, chapter and lesson type are under expandable teaching details.
Scene creation also offers six localized style presets (3D cartoon, 2D cartoon,
flat vector, watercolor, paper-cut and realistic illustration) and an editable
500-unit style description. Choosing a preset fills that description; typing
custom text preserves it verbatim. An empty value leaves style to the brief.
The optional `educationContext.visualStyle` is saved with the task before Chat
activation, not appended to or substituted for the user's brief. Switching routes
retains the input in the form but omits it when creating plain/import tasks.
Both planning entrances treat the saved style as an explicit user requirement
and carry its medium, palette, materials, lighting and exclusions into the
approved visualBible and page intents. Age alone cannot override it. Host master
prompts no longer force a hand-painted picture-book fallback for legacy plans.
Approval and cover selection retain their existing lifecycle; changes after
approval still require plan revision and invalidate affected asset bindings.
Existing paid images are not silently regenerated.
Both planning entrances describe concrete original identities for generic lesson
characters in the visual bible: silhouette, proportions, face and color/outfit
combinations. Generic animal names do not imply commercial mascots. Preserve
required names, species, count, style and explicit appearance requirements.
Originality corrections revise the combined design consistently across pages,
rather than just swapping an accessory; approved identities otherwise remain
unchanged. The visual-master planner and actual provider prompt carry the same
original-character guidance, including the deterministic Host fallback and
legacy plans without a visual bible. It stays within the existing 4000 UTF-16
unit limit. Image size remains 1280x800 / 16:10; the MAIC layer-split prompt,
human approval gates and llm-ha relay role are unchanged. This prompt guidance
reduces accidental resemblance; it does not certify originality or supplier
acceptance, and existing images require explicit revision/regeneration.
When a later page's deterministic visual-master prompt exceeds that limit, Host
shortens its repeated generic art instructions before preparation. The approved
visual intent, visual bible, required objects, exact display text, additional
instructions, plan hash and cover style reference remain unchanged. If even the
compact prompt cannot fit, Host still rejects it before image submission.
Changing stage or subject preserves entered grade/custom-subject text; an
incompatible full-English option is reset. The dialog traps keyboard focus,
including its textarea and expandable details, and blocks duplicate submission.

Creation saves the task and teaching settings before activation, then puts the
exact brief in the owning Chat composer for review and explicit send. It does
not automatically submit a model request, import a file or pay for media. The
existing home draft and attachments are retained. Empty briefs do not replace
drafts, failed creation leaves the form available, and navigation fences prevent
late results from installing a brief into another Chat. Unsent text retains the
existing in-memory composer-draft lifetime; only submitted messages are durable.

## Saved requirements

Host RPC `courseware.task.updateEducation` accepts exactly
`{sessionId, expectedEducationContext, educationContext}`. It uses the existing
strict schema, 500 UTF-16 units per string and 4096-byte task bound. The complete
new context replaces the old; unspecified existing fields must be preserved.
Host serializes updates and rejects stale context, any previous scene approval,
or imported/generated source attachment. Task identity and unrelated fields are
unchanged. Later teaching changes use existing reviewed revisions. No migration.

## Routes and human decisions

- **Ordinary PPT:** keep PPT Master and SVG/notes/final-quality gates. Main Chat
  opens page preview/editing, requests checked final export and opens saved PPTX.
  Card and workbench share project inspection; quality rules are not duplicated.
  **Refresh status** re-inspects the ordinary project's saved inputs/report and
  exports even when Chat is idle. A failed or stale quality report disables
  export and offers **Repair current pages in Chat**, using the same bounded
  report excerpts and repair request as the retained workbench. Repair preserves
  the current project/pages and requires both official planning and final SVG
  checks plus saved page narration. It does not synthesize a passing report in
  the renderer. A later refresh or completed Agent turn exposes the new result.
  The ordinary project inspector also owns the card's stage and initial hint;
  the parent does not infer ordinary readiness from the task attachment flag.
  Before a project is referenced, the stage is requirements; an active Agent shows working;
  inspection, pending pages, failed/stale quality, a changed export, preview-ready
  pages and a current PPTX each have distinct translated stages. Once a project
  is referenced, the card stops asking the user to supply a topic again.
- **Scene:** show actual draft text, visual intent and narration. Trusted UI pins
  approval to the reviewed hash, verifies its receipt, then prompts the same Chat
  to advance. Readiness names missing reference, clean background and foreground
  objects per page, duplicates, identical images, archive gaps and size overflow.
  Compilation still validates bytes. References precede dependent assets.
- **Images:** show exact prompt, real quotation and any private reference. An
  unchecked fee/egress consent and valid quote are required for submission.
  Unknown outcomes query the original request. Human preview/selection uses
  existing selected-intent CAS and then continues Chat. Preparing never pays;
  readiness never selects. Revised prompts may create new intents; exact dedup
  and recovery remain service-owned.
  Image rows show the saved submission phase, task/fee status and provider error
  code. Unknown receipts stay query-only; a definite rejection does not offer a
  status retry or silently create another paid request.
- **Import:** use the existing authorized picker/token import, then open saved
  PPTX. Cancellation preserves the same task for retry. The model cannot choose
  arbitrary file paths. Before selection or an active Office binding, Chat may
  collect requirements and save pre-import teaching settings. It reads task
  readiness and requests the in-Chat picker or Open PPT editor action; it cannot
  claim to have inspected pages/notes. Source inspection and editing still need
  native-bound tools; file/shell tools and local converters are not an import or
  editing substitute. Existing notes, narration and effects use editor APIs.

Preview/Office may open their artifact work panel; no workbench form is needed
for generation. Existing editor review and publication controls remain available;
candidate review also has the main Chat entrances described above. Collaboration,
animation coverage and media canvas are unchanged.
Images retain individual confirmation/selection; no bulk spend or paid retry.
The question/narration Generate action obtains its quote internally, submits once,
then polls for a bounded period and adopts verified audio automatically. It shows
no separate quote/fee-confirmation or refresh controls; insufficient points is a
clear error. Uncertain tasks keep their original identity and cannot be silently
resubmitted. Other status refresh remains explicit or Chat-driven. Whole-plan
approval/asset invalidation remains unchanged; narration-only draft changes do
not gain automatic reuse of paid assets.

## Editing after generation

After opening Office, the same Chat switches to the existing `ppt-edit` skill
and finite native tools for all three task types. An ordinary task must not
return to its older SVG to apply a native edit. Native edits are unsaved until
the user explicitly saves; changed source bytes require the existing reviewed
page association before teaching can be edited again.

For PPTX, Desktop waits for a valid native bridge context matching the opened
document and access mode before publishing editor readiness. WiseOffice's
`document:opened` acknowledges construction and can precede SDK readiness.
Only its two known loading responses are polled, within the existing opening
deadline and cancellation scope; other failures stop opening. This also applies
when reopening an adopted candidate, so a clean teaching sidebar can refresh
against the replacement instead of consuming its hint before the SDK loads.

Narration and reviewed page candidates resolve their effective model through
the same Main launch resolver as Chat and scene compilation, including inherited
defaults and thinking level. They do not write provider/model fields into the
session. Before completion and before staging/retaining a result, recheck saved
session configuration, effective defaults, active scope and current source/teaching.
A changed model or thinking level rejects the candidate. Unavailable resolution
does not start a completion. Narration candidates use the saved Office page text
and remain pending until explicit human review/adoption; this neither rewrites
the PPTX nor generates audio.

retries on the same deterministic length failure. A terminal truncation remains
an unfinished turn and never certifies saved narration, TTS or course completion.

### Single-question Quiz pages

Generated and natively authored Quiz slides contain exactly one question in all
interaction modes. Separate questions require separate physical slides, inserted
between relevant body slides without reducing the requested body page count.
Planning, Host plan approval, native saving and PPT compilation enforce this rule.
The teaching sidebar shows the question and options first, autosaves edits, and
keeps feedback settings collapsed. It has no question-list controls or redundant
manual save button. Course preview is enabled independently of unrelated native
body animation conversion status; unsupported native timeline conversion still
blocks complete MAIC export.

## Assessment sidebar header

Quiz and chapter-interaction pages reuse the ordinary native Teaching Flow
header, status row and icon controls. Only the content below that header changes
to the corresponding assessment form. Undo, redo, save, refresh and preview use
the canonical draft on these pages; they must never write native body teaching
actions. Autosave remains active. No duplicate assessment toolbar is rendered.

## Persisted speech animations

The shared saved-media completion path materializes speech animation cues into
native PPTX timing after every saved speech has adopted its audio. This applies
to PPT Master, scene generation and import; it does not depend on opening each
page in Office. Reading media context also resumes an interrupted local export.
The authoring runtime resolves logical objects through the verified import
mapping, writes finite SDK-compatible behaviors, preserves unrelated native
timing and reparses the result before adoption. Repeating completion is idempotent.

Main adopts the bytes through the existing native-save journal and source CAS,
retaining logical identities and archived audio. Export failure must retain
successful TTS receipts; retrying local animation export must not repurchase audio.
Missing/ambiguous objects, locked pages, unsupported source timing and stale source
fail before replacement. Existing legacy native-step bindings require explicit
reassociation before extending the native sequence.

WiseOffice speech playback may schedule saved native effects against the speech
clock, including different entrance/exit effects on one object. It must never
create an effect absent from the saved native slide. Missing effects are an
incomplete export, not successful animation playback.

## Optional native teaching materials

The three preparation entries keep their generators and converge on the current
native teaching context. Attach UTF-8 TXT/Markdown directly or Word/PDF through
the existing authenticated document parser. Parsing itself never generates a
lesson. Empty, invalid UTF-8 and oversized text fails visibly. Structured formats
retain the document service's existing supported cases; scanned PDF has no local
OCR fallback. Raw extraction uses `text` before semantic summaries for fixed
scripts. Host stores exact extracted text immutably in a task/workspace-scoped KV
record; `sourceId` survives restart and is not a local path.

`courseware_narration_import` accepts optional script and/or lesson-plan roles.
Use a source ID for attachments and text only for user inline material. Preview
with `apply:false`; accept with `apply:true`. A final script chooses `preserve`;
a draft requires an explicit treatment (`revise` or `generate-missing`). Page
headings bind to original logical IDs, never later display ordinals. Unlabelled
segments require explicit assignments unless the neighbouring range has exactly
one original page. Text is not passed through a speech model in the preserve
path. Unknown, missing and conflicting assignments remain visible; no filler is
created. Explicit silent pages remain silent. Unique existing speech with exactly
the same words retains its identity and adopted audio. Music/video/native
animations and existing assessments are retained.

Lesson-plan units carry exact source excerpts and many-to-many page bindings.
Unmatched units and unverified activity identities block complete status.
`courseware_activity_insert` creates one authorized missing independent Quiz or
checkpoint through the existing assessment projection. The exact visible text,
answer/reference, separate question speech and plan binding share native
Undo/Redo and source save. Answer evidence must occur in the accepted plan or
real page text; objective answer labels must be contained in it. Identical visible
question candidates require explicit identity reconciliation instead of insertion.
Confirmed existing activities are reused, including after an uncertain reply.

Both tools retain current Chat/turn/source/teaching/editor-generation fences and
require a capable editor. Partial script writes save successful pages and report
failures. On resume, exact adopted speech/audio is reused. Coverage checks report
manual divergence, missing/deleted anchors, unmatched copied speech and missing
activities. They neither overwrite edits nor claim readiness from a parse receipt.
Preserved script can use `repairRequiredTeaching:true` for focus/effects and
required media without replacing words. Existing media services still own quotes,
original provider orders, adoption, timing and native effect persistence.

### Source-grounded automatic lesson mapping

`courseware_narration_plan` resolves exactly one immutable source ID or inline
user text and reads all real native page text/notes. The selected narration model
extracts ordered teaching/Quiz/checkpoint units and proposes stable page mappings.
Main validates exact source excerpts and exact live page excerpts, finite types,
unique IDs and real pages; it rereads content and model ownership after inference.
Unmatched units remain visible. A unique existing question with exact normalized
source wording can retain its real activity ID; ambiguous matches remain unbound.
No default Quiz quota, invented answer or generated lecture is accepted here.
Explicit user requirements remain the priority for subsequent activity insertion.

`apply:false` previews canonical enrichment. `apply:true` adopts through the same
native material/history/save path. A caller can instead import preview units with
the original source ID, avoiding another model call. Existing accepted plans are
returned without inference or mutation; a different source reports
`requiresExplicitReplacement`. Existing script policy, speech/audio, original
anchors and approved scene/PPT-master teaching requirements are preserved.
Inference accepts at most 100000 source characters, 100 pages and 300000 serialized
evidence characters; larger material fails explicitly, never silently truncates.
This tool requires an editor supporting enrichment v1. It does not create pages or
purchase media: missing mapped activities use `courseware_activity_insert`, and
the established narration and assessment-media tools consume the accepted plan.

### Native full-deck audio recovery

`courseware_media_refresh` additionally accepts `{kind:"tts", recover:true,
sourceSha256}` with optional `pageNumbers`, `model` and `voice`. This native-only
mode rereads each stable logical page and speech before adoption. It keeps any
valid attached speech audio, queries original task receipts (including unknown
submissions), and downloads/decodes/adopts only ready verified audio. It never
quotes, submits, replaces failed tasks, or synthesizes missing speech. Multiple
matching orders require an explicit original intent ID. Prepared, unknown, failed,
locked, missing and stale targets remain visible; running orders remain pending.
Successful pages are saved even if another page fails. Per-result saved state,
failures and whole-scope audio readiness are reported separately. Repeating recovery
retains already adopted audio and does not download it again.

Automatic native media preparation reuses the exact current page/action/text/model/
voice intent before obtaining a quote. Only a prepared original can be submitted;
submitted and unknown orders are returned for refresh. Existing valid audio is
retained. Explicit sidebar regeneration keeps its existing new-attempt semantics.
Native context excludes already voiced actions from automatic jobs and exposes
ambiguous original orders rather than selecting an arbitrary voice. Explicit
single-page refreshes also expose per-intent terminal states and preserve partial
adoption through the same save wrapper.

Native completion checks use the fixed player's speech-animation sequence validator.
Duplicate entrances report ANIMATION_TARGET_CONFLICT and prevent ready status.

When the work panel and automatic teaching continuation open the same PPTX
concurrently, identical open requests share initialization. Teaching context and
automatic opening wait for the in-flight document open before querying the native
bridge. A rejected/cancelled open remains an error; a reader must not silently
read a replacement document. No generation or adoption is replayed to wait for
editor readiness.

### Document-scoped native execution

Native narration, activity and media tools resolve their source from the owning
Host session/task, including its workspace and real source path. Viewing another
Chat does not revoke that document binding. An already open target uses its live
editor and saves its unsaved changes before reading a saved source baseline.
Read-only, changed-workspace and uncertain-save failures never fall back to disk
or another document. Canonical-only classrooms retain their saved workflow.

Closed PPTX targets use one hidden WiseOffice worker. The same native teaching,
candidate, assessment, media and playback-preflight services run in both contexts.
An imported PPTX without native teaching is activated by the same engine command
as a visible editor. Native readiness acknowledges engine initialization and must
not depend on sidebar DOM, sidebar visibility or the selected Chat.

Native tool calls and explicit editor open/close requests share an ordered lane.
An open request captures and revalidates its original Chat/workspace after waiting.
Before opening a visible document, the hidden worker saves and releases its current
document; the visible editor then loads the latest committed bytes. Writes already
dispatched are flushed even after cancellation. A failed flush retains its editor
and blocks handoff until recovered, without replaying provider submissions. Source
CAS, native export identity checks, archived revisions and existing media intent
deduplication remain authoritative. This first implementation serializes native
tool execution across documents to bound memory; scene/image generation outside
this lane remains concurrent. It does not introduce an additional provider queue.

### Saved playback-effect preflight

Once native narration audio is complete and no original media job is pending,
`courseware_media_context` parses the saved PPTX and validates its effects with
the same `projectPlaybackAnimations` resolver used by fixed conversion. Results
are cached only for the exact saved source hash. The source and teaching revision
are checked after asynchronous work. This does not create a publication snapshot,
purchase media, or prove natural audio completion. Errors carry page IDs/numbers;
safe narration-binding corrections use the existing bounded, five-page repair
loop and preserve text/audio. Explicit native-sequence or missing-source failures
remain actionable errors rather than prompting a blind regeneration.

Saved speech owns its targets' playback animation clock. An old editor can leave
unbound native mirrors behind after a repair; conversion suppresses competing
unbound timing, retains unrelated native effects and reports
`PPTX_ANIMATION_SPEECH_OWNED`. Explicit native teaching bindings are not silently
rewritten. Source PPTX bytes remain untouched. Multi-part speech pulse/rotation
uses the same shared-center wrappers as native group timing; it is not projected
as independent component transforms. Group-only wrappers have no click steps.

Required-object descriptions are resolved against verified eligible object names,
aliases and roles, with every whole word and a unique target required for the
role-based match. An unresolved description is not proof that a visual is absent.
The existing visual review can verify and save its planned alias, within the
normal repair budget; actual missing visual content still requires source repair.

Release/test candidates must contain the rebuilt WiseOffice bundle as well as the
desktop main process, player/converter and agent-runtime. A desktop-only rebuild
does not update native editing behavior. Keep bundle hashes alongside evidence.
